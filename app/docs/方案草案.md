技术选型

推荐采用：

\- Electron

\- React + Vite + TypeScript

\- pnpm

\- Zod 负责运行时 JSON 校验

\- Vitest + Playwright 负责单元和界面测试

选择 Electron 的原因是应用需要直接读写本地 JSON、启动 BAT/PowerShell、持续读取 stdout/stderr，并与 Windows 上的 Godot Optimizer 协作。纯浏览器方案做不到这些；Tauri 会额外引入 Rust 和命令权限配置，目前收益不足。

Renderer 不直接访问文件系统或执行命令。所有高权限操作放在 Electron Main Process，通过小型、类型化的 preload API 暴露给 React。

关键实现事实

\- 当前 map/ 已被 Git 忽略；本机现有 G5 1 个节点、G6 18 个节点。

\- 普通战与 Boss 的结果结构略有差异，但都提供 best\_result、verified\_baseline 和 improvement\_vs\_baseline。

\- 普通节点正式结果会删掉大候选列表；Boss 结果仍可能保留 ranked\_candidates。

\- --c 实际解析的是 result.txt，因此 V1 应继续调用它，而不是自行从 JSON 拼装 baseline。

\- 优化失败时旧的正式结果不会被覆盖，并会写出 .result.failed.json。应用不能因为“结果文件存在”就当作本次成功，必须同时检查退出码、任务快照和结果时间。

\- 多个外部 Optimizer 任务会竞争同一套 work/full\_recovered 和 results/latest.\*，因此应用必须设置全局单任务锁；Galaxy 批量任务必须串行。

\- Galaxy 重跑的“方案发生变化”应比较：

best\_result.formation\_key

vs

verified\_baseline.formation\_key

不能根据 Used FR，也不能只根据结果是否更优。formation\_key 已包含位置、舰种和 Loadout，符合 PRD 的判断标准。

Node 版本 JSON 保持现有 Optimizer 格式，不向里面塞管理字段。版本名称、默认版本等信息单独保存在 meta.json。

Common 同样保持当前四字段格式，默认配置和显示名称放在独立元数据中。

runtime/ 只保存可重建的搜索摘要、配置哈希、时间、退出码和结果路径；完整结果仍由 fleetSimulation 管理。

Optimizer 调用边界

应用只依赖一个内部接口：

runOptimizer({

&#x20; galaxy,

&#x20; node,

&#x20; mode: "search" | "copy",

&#x20; nodeConfig,

&#x20; commonConfig

})

该适配层负责：

1\. 验证 Galaxy、Node 和 JSON。

2\. 阻止未保存配置运行。

3\. 以临时文件加替换方式保存正式配置。

4\. 将选中版本复制到 fleetSimulation/map。

5\. 启动现有 BAT 并流式返回输出。

6\. 记录本次 Node/Common 内容哈希。

7\. 退出码为 0 后才读取正式结果。

8\. 校验结果确实属于本次任务。

9\. --c 成功并重新读取 map JSON 后，才覆盖当前 Manager 版本。

React 页面只认识该接口，不知道 BAT、PowerShell 或 Godot 的具体路径。

首个实现里程碑

建议第一轮编码只完成一个薄的端到端切片：

1\. 建立 Electron/React/TypeScript 工程骨架。

2\. 建立 Node、Common、元数据和结果的 Zod schema。

3\. 实现原子 JSON repository。

4\. 实现现有 map/ 的显式导入预览；未经确认不覆盖 app/data。

5\. 完成 Galaxy/Node/版本/Common 选择和只读配置显示。

6\. 实现单任务 Optimizer Adapter。

7\. 可以选一个节点、保存、运行、查看日志并解析 Best Found。

8\. 用假 Optimizer 做自动化测试；真实 Godot 只做一次人工烟雾测试。

第一轮暂不做：

\- 完整版本 CRUD

\- 模板管理

\- --c 同步

\- Galaxy 批量重跑

\- 完整 Formation/Loadout 编辑体验

这样可以先验证最有风险的文件边界、进程生命周期和结果关联，确认后再扩展全部 P0。

一个待确认的数据策略

app/data/ 作为正式数据源，但默认继续 Git 忽略，保持当前玩家配置“仅本机”的性质；不提交其中任何个人配置、schema、示例或占位文件。
