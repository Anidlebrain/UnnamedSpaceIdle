# 主线泰坦联合搜索：源码研究与开发设计

更新：2026-11-07，当前适配 0.90.0.1。以下原始推导以 0.85.1.0 为背景；当前命令、输入契约和门槛以 [README](../README.md) 为准。

0.90 的关键修正已体现在代码中：统计伤害/护盾不再包含校准战斗倍率，外部倍率分别为统计值除以数据库基数 4 / 30；校准值直接注入 `VeilController.alignment`，由原版 `WaveSpawner` 降低敌人强度并执行上限。不得再套用下文旧版的玩家校准除法。`ships2` 与 `ships` 合并读取，新增阵列技能、80 级激光/加农炮分支、30/40 级冲击波分支、70 级护盾及 50 级阵列里程碑按新版数据生成。Galaxy 12 解锁状态单独录入并作用于 165+ 原生缩放。

新版来源为安装目录 PCK 的只读校验备份，经已有 GDRETools 流程恢复到独立项目副本；没有修改游戏目录或读取正式存档。截图只用于理解需求，不作为完整玩家参数。正式游戏玩家状态对照和临界配置实时/固定差异仍需验证。

## 1. 确认后的目标

### BOSS：一次击杀

`boss_once` 在区域末端运行真实首领战。只要一个合法、可复现的战斗样本击杀即可返回 `KILL_FOUND`；不施加挂机的稳定门槛，不要求多个随机种子均获胜。记录这次成功的初始状态、种子、耗时和事件轨迹；复现验证是检查模拟器一致性，不是增加成功率门槛。

同预算未杀掉仅报告 `NO_KILL_FOUND_WITHIN_BUDGET`，不能说无解。残余血量/剩余部件只用于探索，不能包装成击杀。已经击杀后不必继续花时间优化击杀速度。

### 挂机：当前区域的最远稳定距离

`farm_distance` 的决策变量包括距离。先满足稳定判据，再最大化距离；同距离可按护盾余量、击杀周期等选择。收益率是辅助输出，不代替距离目标。

建议第一版默认验证策略（尚未性能定标）：至少 3 个不同验证种子，每个至少 10 个完整巨型敌人循环、且至少 120 秒模拟时间；无死亡、无撤退、无距离回退。加单循环/总模拟时限，不能用无限拖延战斗冒充稳定。候选探索种子和最终验证种子分离。是否达到上述门槛必须随结果输出，有限测试不证明无限挂机绝对安全。

保持位置而非推进；首轮从满盾、零阵列充能、无临时技能开始；后续轮次**不人工重置护盾、充能、技能或定时器**，仅保留原版的重置行为。原版巨型敌人死亡会回满玩家护盾并清阵列状态，不能把它删掉，也不能在每个普通波次额外加一次。

这里的挂机先定义为原版在线战斗保持位置；若要保证退出游戏后的离线结算收益，需要另验 `BattleArea` 的 offline 资源/推进路径，不能直接拿在线生存验证替代。

## 2. 推荐录入什么

目标是保存一份玩家档案，再独立选择 `sector + layer + mode`。静态指**一次搜索期间冻结的玩家快照**，不是所有进度永远不变。换区域不重录；升级、换非搜索系统配置或推进层域进度后更新档案。

### 必须知道、但可以合并录入的玩家信息

| 信息 | 推荐输入方式 | 为什么需要 |
| --- | --- | --- |
| 已解锁核心 | 勾选激光、加农炮、冲击波；Titan 舰体/阵列/护盾作为支持前提 | 数据库存在不表示玩家已解锁 |
| 核心等级约束 | 三种武器的可达到等级，阵列等级、护盾等级；同类不同槽位有差异时展开覆盖 | 计算基础值和开放技能；冲击波升级成本与另外两种差异很大，不能复制等级假装可负担 |
| 外部泰坦伤害加成 | 一个合并量，或用下面的参考面板校准 | 免填研究、计算、设施、碎片、模块等全部来源 |
| 外部泰坦护盾加成 | 一个合并量，或参考面板校准 | 决定生存能力 |
| 外部阵列容量 | 一个表象域容量基准，记录对应阵列等级 | 还要自动加入/剥离阵列固定里程碑，不能双算 |
| 校准值 | 伪本影域、半影域各一个数值 | 原版根据 alignment 算该层域的战斗加成；不能通过区域编号推导玩家校准值 |
| 层域进度 | 各层域本轮最高区域、本影合并边界，必要的重整状态 | 控制首领可挑战条件、实际层域和敌人额外倍率 |
| 额外战斗状态 | 是否使用手动技能/自动技能、其有效强度与持续时间修正；是否有特殊充能/射速等外部修正 | 仅出现非默认影响时补录，不能默认为玩家拥有所有能力 |

基础阵列充能率若经来源审计只有默认值，就自动使用默认值；存在额外修正才录入。引擎速度只在入场/导航/撤退时间实际影响评价时需要，不能要求玩家为静态目录检查录入。

**当前没有经过原生 A/B 验证的“只填两个倍率就准确”的输入方案。** 上表是建议的数据边界，必须用参数归一化和基准战斗验证关闭遗漏后才能冻结为正式 schema。

### 首选输入：统计总览 + 可达到等级（根据用户追加截图确认）

用户追加截图中的界面由 `SummaryStatPanelInfo.setup_stat()` 调用 `PlayerInfo.get_detailed_stat_modifiers(stat, -1, "")` 得到，不是简单显示 `PlayerInfo.stats`。后者的内部聚合用途不同，不能混用。

该总览过滤了普通核心自身的等级和局部里程碑加成，也不包含 `turret` 专用支持路由倍率。因此可以录入该页的两个数值，无需为了这两个数值额外记录当前三门武器的所有分支。截图“负影响升级”来自单独的 `find_missing_upgrades()` 扫描；它出现不表示其局部减益已经乘进总览，不能看到提示就反向除一次。

总览显示的是以数据库统计基数计算的总值，而不是以 1 开始的纯倍率：当前 `titan_damage.base = 4`、`titan_max_shields.base = 30`。本机数据中这两项除核心等级外没有外部 Flat/Additive 来源，归一化工具会审计这一条件。

```text
伤害外部倍率 = 统计泰坦伤害 / 4 / 参考层域战斗倍率
护盾外部倍率 = 统计泰坦最大护盾 / 30 / 参考层域战斗倍率
```

截图的 `2.20e20` 和 `2.31e21`，在剥离层域之前分别对应约 `5.50e19` 和 `7.70e19`。截图未标识读取时的层域，因此不直接替用户保存成最终基准。

伪本影/半影的当前层域战斗倍率由其校准值计算，本影没有对应的校准战斗倍率；深度全域增益保留在外部倍率里。原版只显示 2 位小数的数值会保留一定误差。

阵列容量总览包含阵列核心的固定容量里程碑，要记录**读数时的阵列等级**，先除层域容量倍率，再减去该等级的固定容量贡献，之后对新候选重新加入。它与“搜索时阵列可达到等级”是两件事。不能用顶部 `23/23` 的整数占用显示替代统计页的原始容量小数。

据此，当前 `normalize` 的常规输入是：统计伤害、统计护盾、统计容量；参考层域；伪本影/半影校准值；参考阵列等级；三种武器、护盾、阵列的目标等级上限。未解锁的普通武器不写入 `core_level_caps`。本机代码的外部充能修正只有层域项，工具据源数据自动填入基础值，省去充能率手填；出现新来源则报需要扩展输入。

统计护甲伤害 `1` 等默认项无需单独填。完整原生适配阶段仍要核验有无非默认射速/射程/临时能力等状态，不能把三个数字等同于全战斗参数已经闭环。

**阵列专属加成已支持参考值反推。** 数据库中 ColossalDestruction/TitanArrayShots 系列成就的 `titan_damage` 使用 `global_hook: array`，不计入无 hook 的统计总览，却会影响阵列核心。`reference_array_base_damage` 配合已录入的参考阵列等级，使用已知全局倍率、层域和固定里程碑反推专属倍率，避免逐个填写成就。当前版本基础伤害为 `400 + 100 × 等级`，达到 30 级乘固定里程碑 1.25；这些常数均由数据读取并校验表达式类型。缺少参考读数时专属倍率保留未知。四层域反推一致性和 30 级门槛两侧已有测试；完整玩家状态对照未完成，仍标记 `ready_for_combat: false`。

### 备选：具体核心面板校准

无法读取统计总览时，可记录一套已知参考装配：所在层域、各核心等级、当前里程碑选择、阵列核心的 **Base Damage**、护盾上限、容量。额外记录普通武器伤害/射速用于交叉核对。这条备选路径尚未实现。它需要剥离已知核心、分支、层域的贡献，比统计总览多录参数。

截图顶部阵列“伤害”是整套序列的汇总，不等于阵列核心 Base Damage，不能拿 `1.19e24` 直接当基础伤害。当前截图也没有完整的核心升级等级和护盾上限，不能据此产生玩家推荐。

优先在表象域、没有临时技能效果时记录参考值，可以减少剥离操作；不能切回表象域时，必须保存原参考层域及校准值。需要保留数值显示精度：四舍五入面板在极限距离附近可能改变结果，输出应带输入精度提示并验证稍低距离。

`PlayerInfo.calc_upgrade()` 使用 `(base + flat) × additive × multiplicative`，还区分 `global / turret / array` 等作用域。支持路由分支会影响其他炮塔；不能用单门武器面板再给所有候选重复乘一次技能。遇到多种未知平坦值/倍率时，一次面板读数不能唯一反推，应补充第二组不同等级的参考值，或提供聚合后的分量，不能猜解。

层域深度全域加成若已包含在外部战斗合并值里，只为记录/进度保存，不再次乘入。校准带来的当前层域加成则在切换层域时计算。内部应标记每个输入是否包含 `core / milestones / depth / alignment / temporary ability`，避免双算。

### 不需要手填

- 区域范围、普通敌人种类/比例/出生规则、首领及其部件、伤害和血量公式。
- 武器基础伤害、射速、射程、弹速、范围伤害、护甲/护盾倍率。
- 核心里程碑的等级门槛、每个选择的实际效果及作用域。
- 阵列元素的容量消耗、攻击数据、下一发/后续发加成、提供途径。
- 区域和层域对应的阵列可选部件目标。
- 三个武器槽、一个护盾槽和自动附加的阵列核心。
- 原版层域的 1.1 充能/1.2 容量规则、Boss 难度倍率等常数。

这些都应从对应版本的原版数据和代码加载。科技/研究进度对固定快照的贡献尽可能汇总，不逐项录入。

### 等级与可负担性必须分清

第一版建议固定核心升级等级，只搜装配/分支/目标/阵列/距离。固定等级由用户填写**可实现的等级约束**；多个同种武器的等级按槽位保存。配置检查不等于已验证资源充足。

如果要让搜索同时分配升级资源，必须额外录入可花费资源、改装返还规则和已购等级，再按原版成本/返还处理；这是另一个搜索维度，不能由等级上限偷偷替代。研究工具当前明确输出 `affordability_checked: false`。

## 3. 已确认的搜索空间

### 核心与里程碑

本机数据中 Titan 有 3 个 Weapon、1 个 Shield、2 个 Utility 槽。`ShipLoadout.gd` 自动再加一个 TitanArray，它不占三个普通武器槽。Utility 暂固定，归入外部玩家加成。

| 核心 | 本机数据的选择 |
| --- | --- |
| TitanLaser | 10、20、30、40、50、60 级各二选一 |
| TitanCannon | 10、20、30、40、50、60 级各二选一 |
| TitanShockwaveCannon | 10、20 级各二选一 |
| TitanShield | 10、20、30、40、50 级固定项，30 级提供 Shield Bolster |
| TitanArray | 10、20、30、40 级固定项 |

不能根据命名推断等级，例如护盾 `TitanShieldMile61` 实际门槛是 50。每个装备槽的分支独立，不假设同种武器必须选相同技能。3 种武器的有序槽位是 27 种，不能在没验证炮塔位置等价之前缩成 10 种无序组合。

当前只有一个 TitanShield 类型，不做不存在的“护盾类型”枚举；保留护盾等级和阵列护盾能力。未来版本新增后由目录发现并重新验证。

### 普通核心目标设置

每个槽独立搜索四个字段：

- 种类优先：None、Regen、Shielded、Armored、Unarmored，以及已解锁 Phasing、Can't Phase、Carrier、Barrier、No Barrier、Torpedo。
- 优先级：Highest/Lowest Max HP、Highest/Lowest HP、Highest Damage、Closest、Furthest。
- 换目标：Keep Target / Change Target。
- 集火/分散：Allow / Avoid。

冲击波额外支持 Biggest Cluster / Closest Cluster，普通激光和加农炮不应获得这两个选项。`Avoid` 在没有目标时会回退，不等价于绝不重复瞄准；应直接调用原版 `Turret.find_target()`。

160+ 的解锁阈值覆盖上面的历史目标选项。截图中文中的重复/未翻译标签不参与 ID 推断，内部沿用原版字符串。

### 阵列：组成、顺序、每发目标都搜索

库存由当前候选核心和选中里程碑推导：每门激光给一发 laser_shot，加农炮给 kinetic_shot，冲击波给 kinetic_honing_shot，自动阵列给 basic_damage_boost。里程碑可提供护盾/护甲/船体增强以及能力。能力类最多一个；其他来源按实际数量累加。

数据库里有 11 种元素，但这不表示玩家有 11 种。`boost_shot`、`overload_shot` 等没有当前候选的合法来源时绝不加入。检查工具在一个激光+加农炮+冲击波示例中推导库存，不让用户把底栏数字当成独立、永远有效的库存。

`SELF / NEXT / ALL` 作用域由 `ActiveTitanElementList._apply_effects()` 和 `TitanElement.apply_buffs_to_weapon()` 处理。支持元素只影响随后合适的攻击，排序确实改变结果。射击顺序间隔为原版 0.5 秒，burst 内部间隔为 0.05 秒；能力由阵列发射逻辑统一触发，不能把能力图标位置擅自解释成独立施法时间。

目标是**每发攻击自己的有序列表**，例如 `1:2 → 1:1 → 2:1`，不是整套阵列共用一个目标。编号是先按层域裁剪部件，再按 System 计数的 1-based 编号。优先目标失效时，原版寻找第一个存活的非 Global 部件，最后回退 Global；不是最低血量。空列表是合法的默认目标策略。

## 4. 区域、层域、距离

内部 Layer 对应 Surface/Antumbra/Penumbra/Umbra = 0/1/2/3。前三种保留公共条目和该层条目，本影保留全部敌人和部件。实际层域还受玩家本影合并边界控制，因此检查工具的层域是**请求层域的静态预览**；必须在正式运行前解析有效层域，不能允许模拟游戏中不存在的组合。

区域 164 的数据库距离是 128000–130000，首领为 ColossalSwarm。具体敌人、部件列表由 `inspect` 输出，切换层域无需重录敌阵。

`WaveSpawner.calc_sector_distance_multiplier_specific()` 会沿之前区域累计缩放，再应用本区域的距离百分比、层域倍率和重整状态；不能只用 `164 - 150` 推算最终敌人血量。部分重整状态能改变倍率，不能默认为已经完成。首领使用原版 `BOSS_DIFFICULTY_MULT=2`；护卫也有额外缩放，不能只把巨型船血量乘二。

阵列充能来自普通泰坦敌人的死亡；每波原始总充能为 max_charge 的 80%，再乘玩家 charge rate。顺序和目标会改变小怪清理、阵列频率、敌方炮塔破坏和护盾压力。仅用阵列一轮理论伤害无法评价推图或挂机。

正式距离范围由原版导航/保持位置解析，不让用户输入两个易错边界。首版可按整数距离；接近区域末端必须检查是否触发首领/换区，不能把首领位置当作普通挂机位置。

## 5. 架构与效率方案

独立依赖链：

```text
版本化原版目录 ──> 参数/环境解析器 ──> 合法候选生成器
                        ↑                  ↓
玩家档案 + 搜索请求          有预算调度器 <──> 原版主线战斗适配器
                                           ↓
                                 成功轨迹/连续挂机验证/报告
```

玩家档案不包含目标区域。搜索请求结构拟定为：

```json
{
  "player_profile": "local/player.json",
  "region": {"sector": 164, "layer": "antumbra"},
  "mode": "farm_distance",
  "search": {"max_wall_seconds": 180, "seed": 164}
}
```

这是**接口设计示例，当前 CLI 不执行它**。不新建另一份战斗公式。原生适配器应复用 `BattleArea + WaveSpawner + PlayerShip + Turret + TitanArrayArea + ColossalEnemy/ColossalPart + Projectile`，在自有隔离工程中对接最小 UI/统计依赖。

### 避免全组合爆炸

1. 启动一次常驻 Godot worker，每个候选重置完整战斗状态；不每场重新启动整个游戏。
2. 先验证用户当前装配用于校准。允许基准失败，失败不能挡住推图探索。
3. 核心、里程碑、目标、阵列及距离联合优化；采用多起点、局部变化和保留一定比例的全局探索。构造性候选保证库存/容量合法。
4. 交换阵列相邻元素、移动增强元素、替换一发目标、改一个分支、改一个武器和联合变化都要有调度机会；不能只排序截图现有的六项。
5. 签名包含源版本、归一化玩家状态、区域/有效层域/距离、各槽分支和目标、有序阵列及各发目标、随机场景和模拟时钟。只能复用同条件的结果。
6. 挂机先粗距离网格，再在有希望的边界细化。对每个距离保留多个配装；更近位置的赢家并不一定是更远位置的赢家。
7. **不能用一次失败做全局二分剪枝**。出生组成、聚集、射程、锁定目标和随机性都可能使可行性不严格单调。即使对固定配置使用二分作调度提示，也要保留远端探索。
8. 短战筛选只用于探索排序；真正死亡/撤退可淘汰该样本，短时间没有杀掉只能记未完成。最终候选必须接受独立种子的长验证。
9. 留出总预算约 20–30% 做最终验证，预算包含初始化与收尾。预备 60 秒/180 秒档作为性能目标，**尚无主线实测，不能承诺已经达到**。根据每场耗时自适应减少候选，避免无限等验证。
10. BOSS 一旦取得已验证成功轨迹即可提前结束。挂机若剩余预算不足最终验证，仅返回此前通过验证的距离；没有已验证结果就明确没有，不把预筛距离发布为稳定距离。

结果只能称“预算内找到的最远已验证距离”，除非真的穷举且完成所需验证。不能称全局最远/最优。

## 6. 准确性的关键阻塞与下一步验收

目前 Fleet 已验证的是 `FleetBattle`，不是主线。主线有多处 `RandomNumberGenerator.new().randomize()`，单独调用全局 `seed()` 不足；还有 `_process`、`_physics_process`、SceneTreeTimer 和 `Time.get_ticks_msec()` 混用，直接大步长调用会改写伤害/换目标顺序。

必须按下面顺序完成，后一步不能用静态目录测试冒充前一步：

1. **静态目录/候选约束**（本次实现）：真实 ID、分支、目标和库存正确；来源版本可追踪；拒绝非法输入。
2. **玩家解析器**：从参考面板或聚合量重建三武器、护盾、阵列数值；切换层域和切换分支与原版 UI 一致。明确等级是否可负担。冻结输入 schema。
3. **原版单场适配**：在独立 `user://` 运行普通巨型敌人循环和首领，测量冷/热启动，确保无正式存档/HTTP/Steam 副作用。
4. **可复现与时钟**：对每个 RNG 入口注入场景种子；对同种子比较实时与固定步长的事件顺序、目标、阵列发射、护盾、部件死亡和结局。先把墙钟与模拟钟依赖列全，再谈加速。
5. **游戏 A/B**：至少覆盖 164 四层域的可达组合、范围伤害/集火/锁定、支持路由、两种能力、阵列换序、首领一杀和连续挂机。截图数据不够，需要一份完整参考快照。
6. **预算搜索**：真实基准验证 60/180 秒吞吐；早停、取消、原生异常、失败不发布、缓存隔离、最远距离边界回归。

当前已运行原生泰坦合成战斗，确认参数注入、阵列开火和连续巨型敌人循环可工作；没有完成真实玩家 A/B、随机复现和加速，不能给出速度倍数、成功率、最优阵列或最终推荐距离。Python 工具不重写战斗规则，原生实验调用恢复出的主线场景。
